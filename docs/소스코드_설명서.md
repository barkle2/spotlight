# Spotlight 1.0 소스코드 설명서

- 기준 빌드: 20261009-230724-55c27214
- 제품 버전: 1.0.0 / 배포 주체: 고용노동부 김동현
- 이 문서는 소스 구조와 처리 흐름을 설명합니다. 소스코드 자체를 동봉한다는 의미는 아닙니다.
- 개발 환경: Windows 11, Python 3.13.13 x64, PySide6/Qt 6.11.2, PyInstaller 6.22.3, hooks-contrib 2026.8.

## 1. 폴더 구조

| 경로 | 역할 |
| --- | --- |
| run_spotlight.py | 실행 진입점과 콘솔 없는 실행의 로그 준비 |
| src/spotlight/ | 프로그램 패키지 |
| assets/spotlight.ico | EXE 아이콘 리소스 |
| packaging/ | 빌드 설정과 리소스 생성 도구 |
| validation/ | 화면 환경 및 배포 산출물 검사 |
| docs/ | 사용설명서·설명서 생성 도구·검증 근거 |
| build/ | 빌드 작업 파일과 빌드 보고서 |
| dist/ | 빌드 ID별 EXE와 실행 의존성 |

src는 소스 보관 영역이고 spotlight는 파이썬 패키지 이름입니다. 상대 import와 실행 진입점, 빌드 설정은 이 구조를 사용합니다. packaging과 validation은 실행 기능이 아닌 개발 도구이므로 루트에 둡니다.

## 3. 시작과 종료 흐름

1. run_spotlight.py가 src 경로를 등록합니다. 표준 출력/오류가 없는 경우 사용자 설정 폴더에 실행별 UTF-8 로그를 준비합니다.
2. app.run()이 단일 실행 잠금을 확인합니다. 두 번째 일반 실행은 안내 후 종료합니다.
3. 첫 실행이 이전 복구 표식을 처리하고 현재 Windows 커서를 복원합니다.
4. QApplication과 공통 창 아이콘을 준비하고 시스템 트레이 사용 가능 여부를 확인합니다.
5. 설정을 읽어 커서·강조원 상태에 반영하고 설정/정보 창과 트레이·효과 관리자를 준비합니다.
6. 마우스 입력을 등록한 뒤 Qt 이벤트 루프를 실행합니다.
7. 종료 시 프리뷰 요청을 차단하고 입력·효과·창·트레이·커서 컨트롤러를 각각 정리합니다. 한 자원의 실패가 나머지 정리 시도를 막지 않습니다.
8. 마지막으로 잠금 핸들을 닫습니다. 스모크에서는 정리 후 시험 보고서를 확정합니다.

실제 코드에서는 이전 커서 복구와 Qt 준비 순서가 나뉘어 있습니다. 컨트롤러를 Qt 생성 전에 준비하여 Qt 초기화 실패에도 최종 복원을 시도하고, 이전 표식 복원은 QApplication 생성 후 기능 시작 전에 수행합니다.

## 4. 설정과 저장

HighlightSettings는 frozen dataclass입니다. 프리뷰 변경은 새 객체로 전달하고 마지막 저장값은 별도로 유지합니다.

- 프리뷰: 실행 화면에 반영하며 파일은 저장하지 않습니다.
- 적용: 실행 반영과 저장이 모두 성공한 뒤 적용 기준값을 갱신합니다.
- 확인: 적용 성공 후 창을 닫습니다.
- 취소·X·Esc: 마지막 적용값으로 복구합니다.
- 전체 초기화: 모든 기본값을 미리 표시합니다. 저장 전에는 취소로 복구할 수 있습니다.
- 적용 실패: 최근 저장값으로 복구를 시도합니다. 복구까지 실패하면 종료를 요청하여 커서 복원을 다시 시도합니다.

색상은 정확한 #RRGGBB 형식을 사용합니다. 정수는 bool과 구분하여 타입·범위를 검사합니다. INI 누락 항목은 기본값으로 보완하고, 읽기/파싱/검증 오류는 전체 기본값과 안내 문구로 반환합니다. 읽기 자체는 원본을 변경하지 않습니다.

저장은 같은 폴더의 고유 임시 파일에 기록·flush·fsync하고 닫은 뒤 os.replace로 교체합니다. 실패는 호출부에 전달하고 임시 파일 정리를 시도합니다.

## 5. 입력·화면 좌표·효과

Raw Input에는 마우스 장치만 등록합니다. 키보드 입력을 수집하지 않습니다. NOLEGACY를 사용하지 않고 nativeEvent에서 (False, 0)을 반환하여 원래 클릭/스크롤과 기본 메시지 처리를 유지합니다.

패킷 크기 조회 → 허용 범위 검사 → 데이터 복사 → 헤더/마우스 구조 확인 순서로 처리합니다. 휠 데이터는 signed short로 해석하고 120 단위로 누적하여 효과 신호를 보냅니다.

강조원과 효과 위치는 QCursor.pos()의 Qt 전역 논리 좌표를 사용하며 화면 배율을 다시 곱하지 않습니다. 강조원은 커서를 추적하고, 클릭/휠은 생성 위치에 고정됩니다. 두 효과는 합계 최대 3개이며 새 효과가 한도를 넘으면 가장 오래된 효과를 제거합니다.

휠 테두리는 생성 당시 강조원 지름 안에서 50%→100% 또는 100%→50%로 변합니다. 마우스가 이동하면 지속 강조원과 고정 효과의 위치는 달라질 수 있습니다.

## 6. 커서 확대와 복구

1~15단계는 32+(단계-1)×16px로 변환됩니다. 현재 사용자 레지스트리의 커서 파일 경로를 읽기 전용으로 검증하고, 사용할 수 없으면 기본 리소스를 사용합니다.

14종을 모두 사전 로드한 뒤 복구 표식을 등록하고 시스템 변경을 시작합니다. 표식 저장이 실패하면 변경하지 않습니다. 적용 도중 실패하면 복원을 시도하고 남은 소유 핸들을 정리합니다.

- Windows 공유 커서 원본은 변경·해제하지 않습니다.
- 시스템에 성공적으로 전달한 핸들은 Windows가 파괴하므로 다시 해제하지 않습니다.
- 미사용/실패 핸들만 프로그램이 정리합니다.
- 복원은 현재 Windows 구성표를 다시 로드합니다. 레지스트리를 과거 값으로 되돌리지 않습니다.
- 복원 성공과 표식 일치를 확인한 뒤에만 표식을 삭제합니다.
- 강제 종료 후 일반 실행은 기본 복구 경로의 남은 표식을 처리합니다.

스모크는 별도 임시 경로를 사용합니다. 실패한 스모크의 표식은 일반 실행의 기본 복구 경로와 다르므로 보고서 경로를 확인하여 복구해야 합니다. 표식을 임의 삭제하여 복구 완료로 간주하지 않습니다.

## 7. 정보와 실행 로그

정보 창과 EXE 버전 리소스는 app_info.py의 식별값을 공유합니다. 패키징 실행은 실제 sys.executable의 SHA-256을 계산하고, 소스 실행은 run_spotlight.py를 계산하며 화면에서 구분합니다. 해시는 설정 파일에 저장하지 않습니다.

정보 창은 한 번 생성하여 재사용합니다. 해시 계산 실패는 다음 열기에 재시도하고 성공값은 같은 프로세스에서 재사용합니다.

| 사용자 파일 | 위치 |
| --- | --- |
| 설정 | %LOCALAPPDATA%/Spotlight/settings.ini |
| 복구 표식 | %LOCALAPPDATA%/Spotlight/cursor-recovery.json |
| 실행 로그 | %LOCALAPPDATA%/Spotlight/logs/spotlight-*.log |

LOCALAPPDATA가 없으면 사용자 홈의 AppData/Local을 사용합니다.

## 8. 빌드와 검증

개발 PC에서 프로젝트 루트를 기준으로 실행합니다.

~~~powershell
python run_spotlight.py
python validation/show_display_info.py
powershell -NoProfile -ExecutionPolicy Bypass -File .\packaging\build.ps1
~~~

build.ps1은 고정 패키지 버전과 spec의 명시적 upx=False를 확인하고 새 고유 폴더로 빌드합니다. create_icon.py는 현재 디자인의 ICO를, version_info.py는 공통 식별값의 버전 리소스를 생성합니다.

Spotlight.spec은 콘솔 없는 폴더형 EXE를 만들며 _internal에 동적 의존성을 둡니다. Qt 가상키보드/PDF/QML/Quick의 지정 미사용 파일을 제외합니다. 인증서 서명은 수행하지 않습니다.

~~~powershell
python validation/verify_distribution.py --build-report ".\build\20261009-230724-55c27214\build-report.json"
~~~

산출물 검사는 16개 항목으로 해시/크기/spec·버전·모듈·런타임 폴더·미사용 Qt·UPX 섹션을 확인합니다. 스모크 모드는 --smoke-test와 --smoke-report를 함께 사용하며 실제 커서 API·입력 등록·복원/정리를 10항목으로 판정합니다. 반드시 기존 Spotlight를 정상 종료한 뒤 실행합니다.

이 검사는 모든 GUI 기능이나 보안제품 통과를 입증하지 않습니다. 해당 빌드에서 사용자 GUI·실제 커서 복원도 별도로 확인했습니다. 기관 보안 검토는 추후 예정입니다.

## 9. 문서 생성과 유지보수

docs/create_manual.py는 docs/manual-images의 실제 PNG 5개를 내장하여 사용설명서.html을 생성합니다. 생성기에 포함된 트레이 메뉴는 예시 그림입니다. 문서 도구는 EXE 실행 모듈에 포함할 필요가 없습니다.

변경 순서: 관련 소스/호출부 검토 → 사용자 적용 → 해당 범위 자동 검사와 실제 확인 → 새 빌드 → 새 해시/보고서 → 문서 이미지·후보 ID 갱신. 이전 빌드 결과를 새 빌드의 검증으로 사용하지 않습니다.

단순 주석 변경은 문법 검사 및 docstring 제외 AST 비교로 실행 코드 불변을 확인합니다. 설명이 검증 범위를 넘어가지 않도록 미확인 환경은 구분합니다.
