# Raw Input 전환 수동 검증 체크리스트

테스트 실행파일, Windows 버전, 마우스 모델, 모니터 배율 및 테스트 일시를 먼저 기록한다.

| 항목 | 테스트 절차 | 통과 판정 기준 | 결과 |
|---|---|---|---|
| F-1 좌클릭 이펙트 | 바탕 화면과 일반 앱 위에서 좌클릭을 각각 5회 수행한다. | 매 클릭 위치에 좌클릭 색상의 이펙트가 정확히 한 번 나타나며, 버튼을 놓을 때 추가 이펙트가 발생하지 않는다. | ☐ 통과 ☐ 실패 |
| F-2 우클릭 이펙트 | 바탕 화면과 일반 앱 위에서 우클릭을 각각 5회 수행한다. | 매 클릭 위치에 우클릭 색상의 이펙트가 정확히 한 번 나타나며, 버튼을 놓을 때 추가 이펙트가 발생하지 않는다. | ☐ 통과 ☐ 실패 |
| F-3 휠 방향 | 같은 위치에서 위로 5회, 아래로 5회 스크롤한다. | 10회의 이펙트가 모두 발생하고 위/아래 방향의 애니메이션이 서로 반대이며 실제 스크롤 방향과 일치한다. | ☐ 통과 ☐ 실패 |
| **F-4 PowerPoint 슬라이드쇼 입력** | PowerPoint 슬라이드쇼를 전체 화면으로 실행하고 좌클릭·우클릭·휠 위·휠 아래를 각각 5회 수행한다. | Spotlight가 포커스를 갖지 않은 상태에서도 모든 입력 이펙트가 누락 없이 해당 커서 위치에 표시되고 PowerPoint의 정상 입력도 차단되지 않는다. | ☐ 통과 ☐ 실패 |
| F-5 설정 창 조작 | 트레이 아이콘에서 설정을 열고 스포트라이트 크기와 클릭/휠 설정을 변경한 뒤 적용한다. | 창의 클릭·휠·컨트롤 조작이 정상이며 적용 직후 이펙트가 새 설정을 반영한다. | ☐ 통과 ☐ 실패 |
| F-6 시작/중지 10회 | 앱 실행→입력 확인→정상 종료를 연속 10회 반복한다. | 매 회 입력이 한 번씩만 감지되고 종료가 지연되지 않으며, 다음 실행에서 등록 실패·중복 이펙트가 없다. | ☐ 통과 ☐ 실패 |
| F-7 종료 후 재실행 | 입력 이펙트를 확인하고 트레이에서 정상 종료한 뒤 즉시 다시 실행한다. | 첫 프로세스가 완전히 종료되고 재실행 시 Raw Input 등록 및 모든 입력 이펙트가 정상 동작한다. | ☐ 통과 ☐ 실패 |
| E-1 RDP/VDI | 지원 대상 RDP 또는 VDI 세션에서 앱을 실행하고 좌·우 클릭과 양방향 휠을 각각 5회 시험한다. | 세션 내 입력이 누락·중복 없이 감지되며 좌표와 휠 방향이 일치한다. 환경이 지원 대상이 아니면 사유와 함께 N/A로 기록한다. | ☐ 통과 ☐ 실패 ☐ N/A |
| E-2 고DPI·다중 모니터 | 서로 다른 배율의 모니터에서 네 모서리와 중앙을 클릭하고, 모니터 사이를 이동해 반복한다. | 이펙트 중심이 실제 커서 위치와 육안상 일치하고 모니터 경계에서 점프하거나 반대 모니터에 표시되지 않는다. | ☐ 통과 ☐ 실패 |
| E-3 1000Hz CPU | 1000Hz 마우스를 연결하고 유휴 1분 및 연속 이동 1분 동안 작업 관리자에서 CPU를 관찰한다. | 이동만으로 클릭/휠 이펙트가 생기지 않고, 지속적인 비정상 CPU 상승이나 UI 응답 정지가 없다. 측정한 유휴/이동 평균과 최대 CPU를 기록한다. | ☐ 통과 ☐ 실패 |
| E-4 report 커서 수 | `dist\spotlight.exe --smoke-test --report validation\artifacts\raw-input-report.json` 실행 후 JSON을 확인한다. | `cursor_count_applied`가 숫자 `13`이고 `input_listener_started`가 `true`이다. | ☐ 통과 ☐ 실패 |
